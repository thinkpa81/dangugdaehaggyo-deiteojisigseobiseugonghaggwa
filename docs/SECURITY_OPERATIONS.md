# 보안 운영 설정

## 현재 접근통제 모델

- 공개 회원가입과 인재풀 등록은 종료 상태이며 관련 API는 `410 Gone`을 반환한다.
- 공지사항·논문(학술대회·저널)·입학안내·모집요강·사진자료실의 목록·상세 조회와 조회수 증가는 공개하되 등록·수정·삭제는 활성 관리자에게만 허용한다.
- 네 콘텐츠의 등록·수정·삭제 버튼은 관리자 세션에서만 표시하고, 서버는 각 관리 쓰기 요청에서 역할·계정 상태·인증 버전을 다시 검증한다.
- `/admin`은 관리자 로그인과 운영 기능으로 연결한다. 비로그인 방문자는 관리자 전용 데이터와 쓰기 기능을 사용할 수 없다.
- 논문 댓글 쓰기 API는 계속 `410 Gone`을 반환하며 기존 댓글 데이터와 스키마는 삭제하지 않는다.

클라이언트에서 관리 버튼을 숨기는 처리는 편의 기능이며 접근통제의 근거가 아니다. 최종 권한 판정은 서버의 관리자 검증 미들웨어가 수행한다.

## 환경 관리자 자격증명

- 운영 환경 관리자는 `ADMIN_USERNAME`과 `ADMIN_PASSWORD_HASH`를 Render 환경변수에서 함께 설정한다.
- 실제 아이디, 비밀번호와 해시는 저장소 파일, Git 커밋·PR, 이슈, 운영 문서, 화면 캡처와 명령행 인수에 기록하지 않는다.
- 비밀번호 해시는 `npm run security:hash-password`의 대화형 TTY 숨김 입력으로 생성한 salted scrypt 형식만 허용한다. 평문 비밀번호를 암호화해 복호화하는 방식은 사용하지 않는다.
- 로그인 폼의 비밀번호 입력은 마스킹하고 HTTPS로 전송한다. 서버 요청 로그와 감사 로그에는 요청 본문이나 자격증명을 포함하지 않는다.
- 환경 관리자 설정 여부와 scrypt 형식은 서버 시작 시 검증한다. 아이디와 해시 중 하나만 있거나 해시 형식이 잘못되면 기동을 중단한다.
- 환경 관리자가 설정된 배포에서는 `/api/admin-bootstrap/status`가 최초 데이터베이스 관리자 생성을 요구하지 않아야 한다.

환경 관리자는 배포 플랫폼의 Secret을 사용하므로 Git에는 자격증명이 남지 않는다. 자격증명을 변경할 때는 새 해시를 생성해 Render Secret만 교체하고 재배포한 뒤 기존 세션을 종료한다.

## 관리자 인증·세션

- 최초 활성 관리자가 없을 때만 `/admin`에 일회성 설정 코드·아이디·표시 이름·비밀번호 설정 폼을 표시한다. 설정 성공 즉시 코드를 폐기하고 해당 폼을 더 이상 표시하지 않는다.
- 최초 설정 이후의 일상적인 관리자 로그인에는 아이디와 비밀번호 두 값만 사용한다. 표시 이름이나 일회성 설정 코드를 다시 요구하지 않으며 비밀번호 입력은 항상 마스킹한다.
- 세션 로그인 성공 시 세션 ID를 재발급해 세션 고정 공격을 방지한다.
- 세션 쿠키는 `httpOnly`, 프로덕션 `secure`, `sameSite=lax`이며 30분 유휴 만료와 8시간 절대 만료를 적용한다.
- 데이터베이스 관리자는 PostgreSQL에 salted scrypt 해시로만 저장한다. 기존 평문 또는 지원하지 않는 형식의 비밀번호 레코드는 자동으로 무효화한다.
- 데이터베이스 관리자 세션은 요청마다 활성 상태·관리자 역할·`authVersion`을 확인하며, 비밀번호 변경 시 기존 세션을 무효화한다.
- 관리자 목록 응답에는 비밀번호, 해시와 이메일을 포함하지 않는다.
- 로그인 실패는 IP 기준 15분에 5회로 제한하고 성공·실패·로그아웃과 관리자 작업은 본문 없는 최소 감사 이벤트로 남긴다.

## 콘텐츠 쓰기 통제

- `POST /api/notices`, `PATCH /api/notices/:id`, `DELETE /api/notices/:id`는 관리자 인증을 통과해야 한다.
- `POST /api/papers`, `PATCH /api/papers/:id`, `DELETE /api/papers/:id`는 학술대회·저널 분류와 관계없이 관리자 인증을 통과해야 한다.
- `POST /api/admissions`, `PATCH /api/admissions/:id`, `DELETE /api/admissions/:id`는 관리자 인증을 통과해야 한다.
- `POST /api/photos`, `PATCH /api/photos/:id`, `POST /api/photos/:id/images`, `PATCH /api/photos/:id/images/order`, `DELETE /api/photo-images/:id`, `DELETE /api/photos/:id`는 관리자 인증을 통과해야 한다.
- `GET /api/photos`, `GET /api/photos/:id`, `PATCH /api/photos/:id/views`, `GET /api/photo-images/:id`, `GET /api/photo-images/:id?download=1`, `GET /api/photos/:id/download`는 공개 열람·조회·다운로드 경로로 유지한다.
- 미인증 요청은 401, 인증됐지만 권한이나 계정 상태가 유효하지 않은 요청은 403 또는 세션 만료 응답으로 거부한다.
- 모든 `/api` 쓰기 요청에 동일 출처 검사를 적용한다. 프로덕션에서 `Origin`이 없거나 허용 목록과 다르면 403으로 거부한다.
- 공지·논문·모집요강·사진자료실 쓰기 요청은 IP 기준 속도 제한과 콘텐츠별 입력 검증을 통과해야 한다.
- 삭제 전에 클라이언트 확인 대화상자를 표시하고, 저장·삭제 중에는 중복 요청과 모달 닫기를 막는다.
- 감사 로그에는 요청 ID, 관리자 식별자, 동작과 대상 ID만 기록하며 콘텐츠 본문·첨부 내용·비밀번호를 기록하지 않는다.

## 사진자료 이미지

- 사진 등록은 관리자 인증을 먼저 통과한 `multipart/form-data` 요청에서만 처리한다. 클라이언트의 등록 버튼 숨김은 편의 기능이며 업로드 권한의 근거로 사용하지 않는다. 관리자 인증 뒤, multipart 파싱 전에 서버 전체 업로드 동시성을 1건으로 제한한다. 파싱 전에 중단된 요청은 즉시 슬롯을 반환하지만 최적화·저장을 시작한 요청은 클라이언트 연결이 끊겨도 실제 작업이 끝난 뒤에만 반환한다.
- JPEG·PNG·WebP 확장자, MIME과 파일 시그니처를 함께 검사하고 요청당·앨범당 최대 12개, 입력 파일당 8MB를 적용한다. 앨범 행 잠금 안에서 기존 장수와 추가 장수를 다시 확인해 동시 요청도 상한을 넘지 못하게 하며, 허용되지 않은 형식이나 손상된 이미지, 제한 초과 요청은 저장 전에 거부한다.
- 허용 이미지는 Sharp로 EXIF 방향을 보정하고 최대 2000×1500 크기의 WebP로 변환한다. 최적화 결과는 파일당 3MB, 한 앨범의 전체 이미지는 30MB를 초과할 수 없다.
- 최적화된 바이너리는 기존 Neon PostgreSQL `photo_images.image_data`의 `BYTEA`에 저장하고, 제목·설명·게시기관·게시일·조회수는 `photo_albums`, 파일명·크기·정렬·대체텍스트는 `photo_images`에 분리한다.
- `photo_images.album_id`는 앨범 삭제 시 함께 정리되는 외래키를 사용한다. 개별 이미지 삭제 뒤 순서를 다시 정규화하고, 앨범에 마지막으로 남은 이미지 한 장은 개별 삭제하지 못하게 한다.
- 공개 목록·상세 JSON에는 이미지 바이너리를 포함하지 않는다. 실제 바이트는 이미지 표시·개별 다운로드·전체 ZIP 경로에서만 전달하며, 안전한 응답 파일명과 정확한 `Content-Type`을 사용한다. 이미지 표시는 ETag 기반 즉시 재검증과 15분당 600회 제한, 개별·전체 다운로드는 15분당 60회 제한을 분리 적용한다. 메모리를 사용하는 전체 ZIP 생성은 서버 전체 동시 2건으로 제한하며, 클라이언트 중단 시 스트림을 취소하되 진행 중인 DB 조회가 끝날 때까지 슬롯을 유지한다.
- 사진 영구 데이터는 Render 로컬 디스크나 임시 업로드 경로에 보관하지 않는다. 기존 Neon 연결과 TLS 검증을 사용하므로 별도 클라이언트 저장소 자격증명을 추가하거나 브라우저에 데이터베이스 정보를 노출하지 않는다.

## 첨부파일

- `POST /api/upload`는 활성 관리자에게만 허용해 비로그인 고아 파일 업로드를 차단한다. 공지에 연결된 첨부 다운로드는 공개한다.
- 공지 첨부 업로드는 IP 기준 15분에 5회, 다운로드는 15분에 120회로 제한한다.
- 한 번에 최대 5개, 파일당 10MB이며 허용 확장자·MIME·파일 시그니처를 모두 확인한다.
- 저장 파일명은 무작위 UUID를 사용하고 다운로드 경로는 basename·확장자·읽기 권한을 다시 검증한다.
- 공지 레코드에 첨부 참조를 등록·변경하는 동작은 관리자 전용 공지 쓰기 API를 통과해야 한다.
- 모집요강 첨부는 HTTPS 외부 주소만 허용한다.

현재 첨부는 Render 로컬 파일시스템에 저장되므로 재시작·재배포 시 사라질 수 있다. 장기 운영에는 만료형 공개 URL을 제공하는 객체 저장소로 이전하고 악성 파일 검사와 삭제·보존 정책을 추가한다.

## 모바일 경로 이동

- 홈 바로가기와 모바일 상단 메뉴의 내부 경로는 학과 소개, 공지사항, 논문, 학과 내규와 입학안내·모집요강으로 이동한 뒤 문서 최상단을 표시한다.
- 다른 경로로 이동할 때뿐 아니라 현재 열린 경로를 다시 선택할 때도 상단 이동을 실행한다.
- 모바일 메뉴를 닫은 뒤 상단 이동을 완료하고, 키보드 포커스와 브라우저 기본 탐색을 방해하지 않는다.
- 자료 메뉴의 사진자료실은 내부 경로로 이동하고, 승인된 외부 Google Drive 공유자료실은 새 탭으로 열어 `noopener noreferrer`를 유지한다.

## 유지되는 공통 보안

- scrypt 해시 구조 검증과 timing-safe 비교를 유지한다.
- 공개 회원가입·인재풀 API 종료와 민감 API `no-store` 정책을 유지한다.
- CSP, HSTS, 클릭재킹·MIME 스니핑·브라우저 권한 방지 헤더를 유지한다.
- 데이터베이스 TLS 인증서 검증과 최소 요청 로그를 유지한다.
- 자격증명, 세션 비밀값, 데이터베이스 주소와 일회성 설정 코드를 클라이언트 번들이나 Git에 포함하지 않는다.

## 배포 후 점검

1. `/admin`에서 마스킹된 비밀번호 입력으로 관리자 로그인이 성공하고 잘못된 자격증명은 거부되는지 확인한다.
2. 최초 관리자 활성화 후 일회성 설정 폼이 사라지고 아이디·비밀번호만 입력하는 일반 로그인 화면이 표시되는지 확인한다.
3. 비로그인 화면에는 공지·논문·모집요강·사진자료실 등록·수정·삭제 버튼이 없고, 각 관리 쓰기 API 직접 호출은 401을 반환하는지 확인한다.
4. 관리자 로그인 후 공지·학술대회 논문·저널 논문·모집요강·사진 앨범의 등록→수정→삭제가 성공하고 로그아웃 즉시 모든 관리 버튼이 사라지는지 확인한다.
5. 잘못된 Origin 쓰기 요청이 403, 과도한 요청이 429를 반환하는지 확인한다.
6. Galaxy Z Fold6 상당 폭과 375px에서 홈 바로가기·모바일 메뉴의 내부 경로가 대상 화면 최상단으로 이동하는지 확인한다.
7. 논문 댓글 쓰기 API, 공개 회원가입과 인재풀 API가 각각 의도한 `410 Gone` 상태를 유지하는지 확인한다.
8. 비로그인 첨부 업로드가 401로 거부되고, 관리자 세션의 허용 파일 업로드·공개 다운로드와 허용되지 않은 파일 거부가 동작하는지 확인한다.
9. 환경 관리자 설정 또는 최초 관리자 활성화 후 bootstrap 상태가 불필요한 초기 설정을 요구하지 않고, 빌드·시작 로그와 프로덕션 번들에 자격증명이 없는지 확인한다.
10. GitHub `main` HEAD와 Render 배포 커밋 SHA가 일치하는지 확인한다.
11. 허용 사진 등록 후 표시·개별 다운로드·전체 ZIP이 성공하고 Render 재배포 뒤에도 동일한 Neon 저장 사진을 조회할 수 있는지 확인한다.
12. 비로그인 사진 등록·수정·이미지 추가·순서 변경·삭제 API가 401을 반환하고, 형식·개수·용량·앨범 총량 제한과 마지막 이미지 삭제 차단이 동작하는지 확인한다.

## 장애·롤백

- 콘텐츠 변조가 발생하면 공지·논문·모집요강·사진자료실 쓰기 경로를 우선 차단하고 감사 로그의 요청 ID·관리자 식별자·대상 ID를 기준으로 조사한다.
- 운영 데이터 복구는 검증된 데이터베이스 백업 또는 정상 데이터 기준으로 수행하며 임의의 테이블 삭제를 하지 않는다.
- 자격증명 노출이 의심되면 Render Secret의 비밀번호 해시와 세션 비밀값을 교체하고 서비스를 재배포한 뒤 기존 세션을 종료한다.
- 비밀번호, 해시, 세션 비밀값, 데이터베이스 주소와 고정 bootstrap 코드를 Git에 추가하지 않는다.
- 기존 인재풀 테이블은 사용자 승인 없는 데이터 삭제를 피하기 위해 스키마에 보존하고 공개 라우트에서는 계속 종료 상태로 유지한다.
