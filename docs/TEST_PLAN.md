# 테스트 계획

## 정적 검사

- `npm run check`: TypeScript 오류가 없어야 한다.
- `npm run test:security`: scrypt 해시, 401/403 권한 미들웨어, 동일 출처, 속도 제한, 관리자 전용 공지·논문·모집요강·사진자료실 쓰기, 논문 첨부·사진 업로드 검증, 논문 댓글 API 종료, 모집요강 정렬과 콘텐츠 회귀 검사가 통과해야 한다. 실제 Express HTTP 통합 검사는 메모리 저장소만 사용해 운영 데이터를 변경하지 않는다.
- `npm run build`: 클라이언트와 서버 프로덕션 번들이 생성되어야 한다.
- `npm audit --omit=dev --audit-level=high`: 운영 의존성의 고위험 취약점이 없어야 한다.
- 실제 관리자 아이디, 비밀번호, 해시, 세션 비밀값과 데이터베이스 주소가 추적 파일·Git diff·프로덕션 클라이언트 번들에 없어야 한다.

## 홈페이지 기능

- 단국대학교 로고를 누르면 `/`로 이동한다.
- “학과 소개 보기”는 `/about`으로 이동한다.
- “입학안내”와 “모집요강”은 `/admissions/guidelines`로 이동한다.
- 최신 공지 목록과 “전체보기”가 공지 라우트로 연결된다.
- 자료 메뉴의 사진자료실은 `/photos`로 이동하고 공유자료실 외부 링크는 새 탭으로 열리며 `noopener noreferrer`를 사용한다.
- `/admin`은 모집요강으로 리디렉션되지 않고 관리자 로그인·운영 화면을 표시한다.
- 비로그인 상태에서는 관리자 로그인 진입 경로를 사용할 수 있고, 로그인 후에는 관리자 화면과 로그아웃 조작을 사용할 수 있다.
- 공개 회원가입 UI와 방문자 개인정보 입력 양식은 없어야 한다.
- 논문 하위 메뉴와 모바일 메뉴가 동작한다.

## 관리자 인증·세션

- 로그인 비밀번호 입력은 마스킹되며 클라이언트 화면·콘솔·네트워크 응답과 서버 로그에 평문을 표시하지 않는다.
- 최초 활성 관리자가 없을 때만 일회성 설정 폼이 표시되고, 최초 설정 완료 후에는 같은 화면이 사라져 아이디·비밀번호만으로 로그인할 수 있어야 한다.
- 올바른 환경 관리자 자격증명은 로그인에 성공하고 `/api/users/me`가 비밀번호·해시 없는 관리자 요약만 반환해야 한다.
- 잘못된 아이디 또는 비밀번호는 동일한 401 응답으로 처리하고, 15분 내 허용 횟수를 초과하면 429를 반환해야 한다.
- 로그인 성공 전후 세션 ID가 달라야 하며 세션 쿠키는 프로덕션에서 `httpOnly`, `secure`, `sameSite=lax`를 유지해야 한다.
- 로그아웃 후 관리자 전용 API는 즉시 401을 반환하고 공지·논문·모집요강·사진자료실 관리 버튼이 모두 사라져야 한다.
- 환경 관리자 변수가 쌍으로 설정되지 않았거나 비밀번호 해시 형식이 유효하지 않으면 서버가 기동을 거부해야 한다.
- 환경 관리자가 설정된 운영 배포에서 `/api/admin-bootstrap/status`는 추가 초기 설정이 필요하지 않은 상태를 반환해야 한다.

## 콘텐츠 접근통제

- 비로그인 방문자는 공지 목록·상세와 첨부 다운로드를 열람할 수 있어야 한다.
- 비로그인 화면에는 공지 등록 버튼, 수정·삭제 버튼과 관리 열이 노출되지 않아야 한다.
- 미인증 `POST /api/notices`, `PATCH /api/notices/:id`, `DELETE /api/notices/:id`는 각각 401을 반환하고 저장소를 변경하지 않아야 한다.
- 관리자 로그인 후 공지 등록→조회→수정→삭제가 성공해야 하며 각 변경 결과가 목록에 반영되어야 한다.
- 관리자 세션이라도 데이터베이스 계정이 비활성화되거나 인증 버전이 바뀌면 쓰기 요청을 거부하고 재로그인을 요구해야 한다.
- 잘못된 Origin의 공지 쓰기 요청은 인증 여부와 관계없이 403을 반환해야 한다.
- 공지 등록·수정 모달은 키보드로 제출할 수 있고 저장·삭제 중 중복 실행과 모달 닫기가 차단되어야 한다.
- 공지 첨부 선택은 키보드로 접근 가능하며 최대 5개·파일당 10MB 제한과 허용 파일 검사가 동작해야 한다.
- 미인증 `POST /api/upload`는 401을 반환하고 파일을 생성하지 않아야 하며, 관리자 업로드와 등록된 첨부의 공개 다운로드는 성공해야 한다.
- 수정·삭제 아이콘 버튼은 최소 44×44px이어야 한다.
- 비로그인 방문자는 학술대회·저널 논문과 모집요강의 목록·상세를 열람하고 조회수를 증가시킬 수 있어야 한다.
- 비로그인 화면에는 논문·모집요강 등록·수정·삭제 조작이 노출되지 않아야 한다.
- 미인증 `POST/PATCH/DELETE /api/papers` 계열과 `/api/admissions` 계열 요청은 각각 401을 반환하고 저장소를 변경하지 않아야 한다.
- 관리자 로그인 후 학술대회 논문, 저널 논문과 모집요강의 등록→조회→수정→삭제가 각각 성공해야 한다.
- 잘못된 Origin의 논문·모집요강 쓰기 요청은 인증 여부와 관계없이 403을 반환해야 한다.

## 논문 첨부파일

- 학술대회·저널 등록 창과 수정 창에서 드롭존 클릭 선택과 마우스 드래그 앤 드롭이 모두 동작하고, 선택된 파일명·용량·제거 조작과 제한 오류가 표시되어야 한다.
- 관리자 세션에서 허용된 PDF·DOC·DOCX·HWP·HWPX·PPT·PPTX·JPG·JPEG·PNG·WebP를 첨부한 논문 등록, 추가·교체·삭제가 성공하고 저장 결과가 목록·상세에 즉시 반영되어야 한다.
- 최대 5개, 파일당 10MB, 논문당 합계 30MB를 초과하는 요청과 확장자·MIME·파일 시그니처가 일치하지 않거나 손상된 파일은 바이너리를 저장하기 전에 거부해야 한다.
- 비로그인 논문 등록·수정·삭제와 첨부 추가·교체·삭제 요청은 401을 반환하고 메타데이터와 바이너리를 변경하지 않아야 한다. 로그아웃 직후 이미 열린 등록·수정 창에서 제출해도 같은 기준을 적용한다.
- 공개 논문 목록·상세 응답은 첨부 ID·파일명·MIME·용량·순서만 포함하고 `file_data`, Buffer 직렬화나 base64 본문을 포함하지 않아야 한다.
- 공개 다운로드는 저장된 원본 바이트와 정규화된 MIME, 안전한 `Content-Disposition` 파일명, MIME 스니핑 방지 헤더를 제공하며 허용된 속도 제한을 적용해야 한다. 존재하지 않는 첨부는 404를 반환해야 한다.
- 첨부 삭제 뒤 순서는 일관되게 유지되고 논문 삭제 시 연결된 첨부 행도 함께 정리되어야 한다. Render를 재배포한 뒤에도 Neon에 저장된 논문 첨부를 같은 URL로 내려받을 수 있어야 한다.

## 사진자료실

- 비로그인 방문자는 `/photos` 목록에서 앨범 제목·게시일·조회수·사진 수·대표 이미지를, `/photos/:id` 상세에서 게시기관과 본문을 함께 확인할 수 있어야 한다.
- 검색 범위와 검색어 제출, Enter 제출, 결과 수·결과 없음·오류 상태와 페이지 이동이 동작해야 하며 최신 게시일·번호 순서가 유지되어야 한다.
- 상세 진입 시 조회수가 원자적으로 증가하고 주 이미지, 현재 위치, 이전·다음 화살표, 썸네일 선택, 자동 재생 일시정지, 앨범 설명, 이전글·다음글·목록 이동이 동작해야 한다.
- 주 이미지와 썸네일에는 앨범 제목과 순서를 식별할 수 있는 대체텍스트가 있어야 한다. 썸네일은 키보드로 선택 가능하고 현재 항목을 알리며, 화살표와 일시정지 조작은 가시적 포커스와 접근 가능한 이름을 제공해야 한다.
- `prefers-reduced-motion: reduce`에서는 자동 전환하지 않고, 사용자가 일시정지한 뒤에는 다음 자동 전환이 발생하지 않아야 한다.
- `GET /api/photo-images/:id`는 올바른 WebP 본문을 표시하고 `?download=1`은 안전한 개별 파일 다운로드를, `GET /api/photos/:id/download`는 앨범의 모든 사진을 순서대로 포함한 ZIP 다운로드를 제공해야 한다.
- 목록·상세 JSON에는 `image_data`나 바이너리 본문이 포함되지 않아야 하며, 존재하지 않는 앨범·이미지와 빈 ZIP 대상은 의도한 404를 반환해야 한다.
- 비로그인 `POST /api/photos`, `PATCH /api/photos/:id`, `POST /api/photos/:id/images`, `PATCH /api/photos/:id/images/order`, `DELETE /api/photo-images/:id`, `DELETE /api/photos/:id`는 각각 401을 반환하고 데이터와 바이너리를 저장하지 않아야 한다.
- 관리자 로그인 후 JPEG·PNG·WebP 사진을 포함한 앨범 등록, 메타데이터 수정, 이미지 추가, 순서 변경, 개별 이미지 삭제와 앨범 삭제가 성공해야 하며 각 결과가 목록·상세에 즉시 반영되어야 한다.
- 앨범 등록과 이미지 추가 창에서 드롭존 클릭 선택과 마우스 드래그 앤 드롭이 모두 동작하고, 선택 파일·제거 조작·형식·개수·용량 오류가 표시되어야 한다.
- 업로드는 메타데이터 4개와 사진 12개가 함께 든 정상 요청을 허용하고, 요청당·앨범당 12개·입력 파일당 8MB를 넘는 요청, 확장자·MIME·파일 시그니처 불일치와 손상 이미지를 거부해야 한다. 반복·동시 추가 요청으로 13번째 사진을 저장하려 해도 거부하고, 최적화 결과는 WebP·최대 2000×1500·파일당 3MB이고 앨범 합계 30MB 이하여야 한다.
- 관리자 인증 뒤 multipart 버퍼링 전에 서버 전체 업로드 동시성 1건을 강제하고, 두 번째 요청은 429를 반환해야 한다. 파싱 전 중단은 슬롯을 반환하되 최적화·저장을 시작한 요청은 연결이 끊겨도 실제 작업이 끝나기 전에는 슬롯을 재사용하지 않아야 한다.
- 화면 표시용 이미지는 15분당 600회, 개별·전체 다운로드는 15분당 60회의 서로 분리된 제한을 적용해야 한다.
- 전체 ZIP 생성은 서버 전체 동시 2건까지만 시작하고 세 번째 요청은 429를 반환해야 한다. 다운로드 클라이언트가 중단되면 ZIP 스트림은 취소하되 진행 중인 Neon 조회가 끝나기 전에는 슬롯을 재사용하지 않고, 작업 종료 뒤에는 다시 다운로드할 수 있어야 한다.
- 마지막 남은 이미지의 개별 삭제는 거부하되 앨범 삭제는 이미지와 메타데이터를 함께 정리해야 한다. 삭제 전 확인, 처리 중 중복 실행 차단과 실패 오류 안내가 동작해야 한다.
- 관리자 로그아웃 직후 등록·편집·삭제 조작이 사라지고, 이전에 열린 화면에서 직접 관리 API를 호출해도 401로 거부되어야 한다.

## 모바일 탐색 및 상단 이동

- 335px, 375px, 768px에서 모바일 메뉴가 열리고 모든 항목을 키보드와 터치로 선택할 수 있어야 한다.
- 홈 바로가기의 학과 소개, 공지사항, 논문, 학과 내규, 입학안내·모집요강을 각각 선택하면 올바른 내부 경로와 화면 최상단으로 이동해야 한다.
- 모바일 상단 메뉴의 학과 소개, 공지사항, 논문, 학과 내규와 입학안내를 각각 선택하면 메뉴가 닫히고 올바른 내부 경로의 최상단으로 이동해야 한다.
- 현재 화면을 중간까지 스크롤한 뒤 같은 경로 메뉴를 다시 선택해도 `window.scrollY`가 0으로 복귀해야 한다.
- 다른 경로로 이동한 뒤 렌더링이 완료된 시점에도 `window.scrollY`가 0이고 제목·상단 배너가 중간에서 잘리지 않아야 한다.
- 홈 하단이나 바로가기 영역에서 내부 경로를 선택한 뒤 100ms, 300ms, 700ms 시점 모두 `window.scrollY`가 0이어야 하며 전역 부드러운 스크롤 때문에 상단 이동이 지연되지 않아야 한다.
- 자료 메뉴는 승인된 Google Drive 공유 폴더를 새 탭으로 열고 원래 페이지의 스크롤 상태를 불필요하게 변경하지 않아야 한다.
- 브라우저 뒤로·앞으로 이동과 데스크톱 내비게이션의 기존 경로 동작을 훼손하지 않아야 한다.

## 반응형·시각 검사

- 1440px: 최대 1440px 래퍼의 지도교수 단일 카드에서 336px 사진 전용 패널, 우측 정보·연구카드 `4·4·2`, 축소된 하단 여백과 그 아래 전체 폭 컨택 카드를 확인한다.
- 1024px: 280px 사진 패널과 우측 연구카드 `4·4·2`, 그 아래 전체 폭 컨택 카드 및 모집요강 목록·검색을 확인한다.
- 768px: 240px 사진 패널·우측 정보와 연구카드 2열, 그 아래 전체 폭 컨택 카드와 모바일 메뉴 전환을 확인한다.
- 375px: 사진 패널 → 교수 정보·연구카드 1열 → 컨택 안내 순서, 검색 컨트롤 전체 폭, 제목·이메일 줄바꿈을 확인한다.
- 335px: 홈 히어로 첫 줄, 모바일 메뉴, 공지 관리 표시와 경로 이동에서 가로 넘침·텍스트 잘림·겹침이 없어야 한다.
- 320px: 컨택 헤더가 아이콘·영문 머리말 첫 행과 한글 제목 다음 행으로 전환되고 `scrollWidth <= clientWidth`인지 확인한다.
- 학과소개 컨택 카드에는 졸업모 아이콘, 확대된 `박사과정 컨택`, `이메일 문의`, `기타 문의` 제목과 최신 안내 문장이 표시되어야 한다. 아이콘은 `aria-hidden`이고 단계·목록 번호는 없어야 하며 확정된 4개 `mailto:` 링크가 동작해야 한다.
- 브라우저 콘솔에 오류가 없어야 한다.
- 사진자료실 목록은 1024px 이상에서 3열, 800px 이하에서 2열이며 카드 이미지의 크롭·제목 두 줄·메타데이터 정렬에 가로 넘침이 없어야 한다.
- 사진 상세의 주 이미지는 4:3 비율을 유지하고, 375px과 335px에서는 이미지·화살표·현재 위치·다운로드와 관리자 조작이 겹치거나 화면 밖으로 밀리지 않아야 한다.
- 1024px, 768px, 375px에서 논문·사진 관리자 드롭존과 선택 목록이 모달 너비 안에 맞고, 긴 파일명·용량·제거 조작이 겹치거나 화면 밖으로 밀리지 않아야 한다.

## 기존 콘텐츠 회귀

- 모집요강 목록에서 제목, 게시 기관, 날짜, 조회수와 선택적 첨부 링크를 확인한다.
- 전체·제목·내용·게시기관 검색 범위, 검색어 공백 제거·한글·영문 대소문자·Enter 제출과 결과 없음 상태가 동작해야 한다.
- 모집요강 목록은 게시일 내림차순이며 같은 날짜는 번호 내림차순이어야 한다.
- 모집요강 제목을 열면 조회수가 서버에서 1 증가하고 갱신된 값이 표시되어야 한다.
- 논문·모집요강·사진자료실의 등록·수정·삭제는 활성 관리자 세션에서만 동작하고 로그아웃 직후 관리 조작이 사라져야 한다.
- 논문 목록·상세에 댓글 수, 댓글 내용과 `로그인 후 댓글 작성` 문구가 없어야 하고 논문 댓글 쓰기 API는 410을 반환해야 한다.
- 공개 회원가입·인재풀 API는 410을 반환하고 방문자 개인정보 입력 양식이 노출되지 않아야 한다.

## 메타데이터·배포

- `og:image`와 `twitter:image`가 `/opengraph.jpg`를 가리킨다.
- 파비콘이 단국대학교 DKU 마크로 표시된다.
- GitHub `main` HEAD와 Render 배포 커밋 SHA가 일치해야 한다.
- Render 환경변수 화면, 빌드·시작 로그와 배포 산출물에 실제 자격증명이나 비밀번호 평문이 없어야 한다.
- 배포 후 Render 기본 주소와 사용자 도메인에서 관리자 로그인, 공지·논문·모집요강·사진자료실 접근통제, Neon 저장 논문 첨부 다운로드·이미지 재조회와 모바일 상단 이동을 각각 확인해야 한다.
